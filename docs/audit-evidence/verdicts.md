## F20 — **CONFIRMED** (P1)
pos_machine's _applyMultiBuy marks the selected qty units consumed=true (offer_engine.dart:216-218) BEFORE testing 'discount > 0' and breaks on an at/under-price set (lines 224-227) with the units left consumed — even when the offer applied zero times and returned null. Direction is one-way (machine discount <= handheld discount, machine total >= handheld total). The handheld is correct per the engine's own documented rule that a unit participates in at most one offer APPLICATION (no application occurred at discount 0) and per merchant intent. Scope caveat: with no overlapping later offer the two engines price identically, so the overcharge requires a merchant config where a multi_buy whose best set is at/under price coexists with a later overlapping offer.
